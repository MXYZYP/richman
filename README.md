# 大富翁 · 浏览器桌游

为亲友聚会制作的网页版大富翁。支持 **中国之旅、世界之旅、世界名城、丝路之旅、长城之旅、黄河之旅、长江之旅、珠江之旅、新疆之旅、山西之旅** 十张地图，手机与电脑均可游玩；可以同屏轮流操作，也可以通过 6 位房间码联机。

**当前版本：v2.14.0 — 复盘导出、成就榜与地图工坊。** 完整改动见 [CHANGELOG](CHANGELOG.md)，游戏首页也可查看更新说明。

## 可以怎么玩

| 模式 | 人数 | 使用方式 |
| --- | --- | --- |
| 单机热座 | 2–6 名参赛者，含电脑玩家 | 在同一台设备上轮流操作，无需联机服务器 |
| 房间联机 | 2–6 名参赛者，含电脑玩家 | 各自使用手机或电脑，通过房间码加入 |
| 只读观战 | 每个联机房间额外 3 席 | 开局前后均可加入，不占参赛名额 |

- 一位真人也能搭配电脑玩家开局，房主可以添加电脑并修改其昵称。
- 买地、收租、盖房升级、抵押、债务处理、破产与胜利结算由游戏处理；每张地图使用各自的规则和卡牌。
- 单机提供两个本地存档位置；单机真人抽到机会或命运卡时，可以重新抽取，接受后才执行。联机和电脑玩家不使用这项重抽规则。
- 联机支持刷新、短暂断线后恢复身份；真人玩家离线时，房主可托管其回合。
- 观众能查看棋盘、资产和战报，但不能掷骰、操作资产、管理房间或托管玩家。观众断线保留席位 5 分钟，主动离开立即释放；不支持在房间内直接切换参赛与观战身份。

## 当前界面

单机和联机共用游戏界面，不是两套独立版本：

- 全局棋盘配合骰子动画、资产面板和战报，当前位置显示拥有者、地皮等级及租金。
- 手机操作区域保持稳定，购买、放弃、结束回合等操作切换时避免按钮上下跳动。
- 五至六人玩家栏保持固定座次和单行高度，可横向滑动；当前行动者自动滚入可见区域。
- 六种颜色搭配不同棋子形状，观众名单与参赛者分开显示。
- 首页有本机战绩面板、成就墙与成就排行榜。成就完全在本机由战绩算出，不联网、不埋点；排行榜是唯一会联网的部分，只有点过“上榜 / 更新我的成绩”才会把数据发出去。
- 首页「地图工坊」可以把 `tools/map-editor.html` 导出的地图装进本机、单机试玩或删掉。自定义地图**只能单机**：联机建房走服务端，而服务端只认内置的那十张图，本机装的图会被直接拒；导入时用的是和正式地图完全相同的校验，不合格会指出具体字段。
- 单机对局可以导出「复盘」：一串文本，别人粘回首页就能重演同一局（同一副牌、同一次掷骰、电脑同样的决策）。复盘与「战绩码」是两件事，前者重演过程、后者只合并统计；同样只做单机，联机不提供。

## 打开游戏

**静态前端：<https://richman.pages.dev/>**

该地址可用于单机游玩。Cloudflare Pages 只托管网页，**不运行联机服务器**；能打开首页不等于能够创建联机房间。若出现“无法连接服务器”，仍可选择单机游玩。

亲友远程联机请使用主机提供的服务地址。临时内网穿透网址依赖主机保持开机、联网和服务运行，因此不作为固定入口写入本 README。

## 装到手机（三种方式，按需选）

| 方式 | 适合场景 | 需要什么 | 现状 |
| --- | --- | --- | --- |
| PWA「添加到主屏幕」 | 自己与亲友用，不进应用商店 | 手机浏览器即可 | **已可用**，无需额外步骤 |
| 鸿蒙原生壳（HAP / App Pack） | 想上华为应用市场分发 | DevEco Studio + 华为开发者账号 | 工程骨架已就绪、已知缺陷已修；打包上架需在装了 DevEco 的电脑上做 |
| Android 原生壳（APK / AAB） | 想上 Google Play 或直接发 APK | JDK 17 + Android SDK + Gradle | **仓库尚无 `apps/android` 工程**，本机也没有上述工具链，暂不可构建 |

- **PWA（建议先走这条）**：手机浏览器打开游戏地址 → 浏览器菜单里选「添加到主屏幕 / 安装应用」。之后有图标、全屏，断网也能进首页壳（联机对战仍需联网）。
- **鸿蒙原生壳**：完整步骤、签名与上架清单见 [apps/harmonyos/README.md](apps/harmonyos/README.md)。关键一条：壳默认从**你自己那台同时托管网页与联机服务的服务器**加载，不要填上面那个只托管静态网页的 Pages 地址，否则会出现「首页能开、建房连不上」。
- **Android 原生壳**：Capacitor 的依赖与脚本已在 `apps/client/package.json`（`cap:add:android` / `cap:sync` / `cap:build:android`），但原生工程还没生成；补齐步骤见鸿蒙 README 第 6 节。

> 三种方式共用同一份前端产物。只要没用到原生能力，**云端模式改完前端部署一次，三类用户同时生效**，不必各自重新发版。

## 本地运行

环境要求：**Node.js 20 或更新版本、pnpm 10.33.2**。私有仓库需要先取得访问权限。

在仓库根目录执行：

```bash
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

打开 <http://localhost:3000>。同一个 Node 服务提供网页与 Socket.IO 联机连接，不需要分别部署两套前端。

如果默认端口已有对局在运行，请使用其他端口启动独立实例，不要关闭原服务。例如在 macOS / Linux 上：

```bash
PORT=3011 pnpm start
```

### 同一 Wi-Fi 聚会

```bash
pnpm party
```

根据终端显示的局域网地址和二维码，让朋友连接同一网络后打开。主机需保持运行，防火墙也需允许访问服务端口。

### 开发与检查

```bash
pnpm dev            # 同时启动前端开发服务与后端
pnpm validate-data  # 检查地图和卡牌数据
pnpm typecheck      # TypeScript 类型检查
pnpm test           # Vitest 测试
pnpm e2e            # Playwright 浏览器冒烟（自动构建前端并起生产形态服务）
pnpm build          # 发布元数据检查、前端构建与服务端类型检查
```

开发时使用终端打印的前端地址。

`pnpm e2e` 先构建前端，再由服务端静态托管 `apps/client/dist`，因此测的是玩家真正打开的那份产物，而不是开发服务器的即时编译结果。默认复用系统已安装的 Chrome（`channel: 'chrome'`），不额外下载浏览器；机器上没有 Chrome 时可先 `pnpm exec playwright install chromium`，再用 `E2E_CHANNEL=bundled pnpm e2e` 切到 Playwright 自带内核。失败时的截图与 trace 落在 `e2e/.artifacts/`。

## 联机部署与存档边界

- 联机需要持续运行 Node 服务，并允许 Socket.IO / WebSocket 连接；仅部署静态网页不够。
- 房间属于创建它的服务实例。不同端口、不同实例的房间不互通，旧网址中的对局不会自动迁移到新网址。
- **客户端断线重连不等于服务端重启恢复。** 当前生产服务的房间状态保存在进程内存中，不要在有人对局时重启、替换或关闭服务。
- 单机浏览器存档与联机房间是两种机制；单机存档不能作为联机服务器的备份。
- 更新时可先另起实例供新对局使用，保留旧实例直到原对局结束。临时隧道也应分别指向对应实例。
- 仓库现有自动发布流程只部署 Cloudflare Pages 前端，联机后端需单独部署和维护。
- 成就排行榜的提交内容只有**昵称、胜场、总局数、资产峰值、玩过的地图数**，外加一个本机随机生成的排行榜编号；不提交登录凭证、房间令牌、对局内容或客户端时间（提交时间由服务端盖章）。编号只用于把同一个人的多次提交认成同一条，换设备或清空浏览器数据后会以新身份上榜。排行榜数据存在服务实例的 `.runtime/leaderboard.json`，与房间一样属于该实例，不随前端部署迁移。
- 地图工坊里的自定义地图只存在本机浏览器（键名 `richman_custom_maps_v1`，最多 8 张），不上传、不同步，清空浏览器数据后需重新导入。它们**与联机无关**：服务端不认识本机装的图，只有单机对局能用；自定义地图也不能引用包内图片（运行时拿不到构建期注册的资源地址），只能用内置图标。

## 代码从哪里看

项目使用 **Vue 3、TypeScript、Vite、Node.js、Socket.IO、Vitest**，通过 pnpm workspace 管理。

| 路径 | 内容 |
| --- | --- |
| [`apps/client`](apps/client) | 首页、大厅、棋盘、资产界面，单机与联机会话 |
| [`apps/server`](apps/server) | 房间生命周期、身份与操作校验、状态广播、静态网页托管 |
| [`packages/engine`](packages/engine) | 游戏状态、回合推进、规则处理与电脑决策 |
| [`packages/board-data`](packages/board-data) | 十张地图、卡牌与数据校验 |
| [`packages/protocol`](packages/protocol) | 客户端与服务端共用的消息和公开状态类型 |
| [`scripts`](scripts) | 聚会启动、版本发布等工具 |
| [`e2e`](e2e) | Playwright 浏览器冒烟：首页、单机开局掷骰、联机建房开局、刷新重连 |
| [`plan`](plan) | 规则规格、架构决策、阶段计划与验收记录 |

联机由服务器决定游戏状态，客户端提交操作并接收公开快照；观战权限也由服务端校验，而不只是隐藏前端按钮。

## 验证与版本记录

v2.14.0 发布前已完成：

- `pnpm test`：117 个测试文件、1894 项测试通过；各工作包 `tsc --noEmit` 与客户端 `vue-tsc` 全部无错误。
- 十张地图在真实服务端网关下各跑一局完整对局直到终局（含电脑玩家、离线托管、交易、拍卖与落盘快照），全程无服务端异常。
- 本批新增五项：单机复盘导出（导出与导入同一局可逐字节重演）、成就墙与成就排行榜（可选上榜）、地图工坊（把编辑器导出的地图装进本机，仅单机可用）、两套地图配色「森林」「沙丘」与「跟随深色 / 跟随地图」两个自动挡、以及鸿蒙原生壳工程骨架。
- 自定义地图沿用正式地图的**同一套校验**（同一校验器、同一规则模块白名单，哈希一律本机重算），地图包内的图片不被接受；排行榜只提交昵称与四个聚合数字，数据落在服务实例的 `.runtime/leaderboard.json`，提交有频率限制、90 天未更新的条目会被清理。
- 建房与房间列表的限流改为复用同一套滑动窗口限流器（窗口长度与阈值不变），服务端新增 `/api/leaderboard` 读写接口并挂在静态托管之前。
- 部署清单共 236 项，其中新增本轮的 `replayCode.ts`、`achievements.ts`、`leaderboard.ts`、`customMaps.ts`、`ReplayDialog.vue`、`MapWorkshopDialog.vue`，以及服务端的 `leaderboardStore.ts`、`leaderboardRoutes.ts`、`slidingWindowRateLimiter.ts` 与各自配套测试，本地预检不再拦截。
- 线上核验：`/healthz` 返回 `200 ok`；首页引用的构建产物与服务器 `dist` 逐字一致，产物内含 `2.14.0`、`复盘`、`成就`、`地图工坊`，复盘与地图工坊各成独立懒加载分块；`/api/leaderboard` 读取返回 `{"ok":true,...}`、非法提交返回 `400`；实机建房成功且地图 `contentHash` 与仓库逐位一致，未知地图被拒为 `Requested map is unavailable.`，建房后房间设置仍按「先 ack 后设置」的顺序单播。

以上为该版本的验证记录，不表示完整自动化端到端测试已经覆盖所有对局，也不代表任意部署地址已经更新。

版本更新由 [`release-notes.json`](release-notes.json) 和发布脚本维护，生成 [CHANGELOG.md](CHANGELOG.md) 并供首页展示。仅更新文档不改变游戏版本号。
