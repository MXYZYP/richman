# 00 · 项目总览与协作约定

> 本文档是整套计划的总纲。**任何 agent 接手任何阶段的工作前，必须先完整读完本文档**，再读对应阶段的文档。

## 1. 项目一句话

把实体桌游《大富翁·中国之旅》做成 **2D 网页游戏**：手机和电脑浏览器打开网址、输入房间码即可 2-6 人在线联机，另支持 3 个只读观战席；单机热座仍为 2-4 人。复刻实体版的棋盘内容和完整规则，仅供 owner 的亲友内部游玩。

## 2. 读者与角色

| 角色 | 是谁 | 职责 |
|---|---|---|
| **Owner（产品负责人）** | 本项目的用户本人 | 决定玩法、规则、体验；提供实体版照片；每阶段试玩验收。**不读代码、不写代码、无法从代码层面发现 bug** |
| **执行 agent** | 被 owner 指派执行某阶段的 AI agent | 按对应阶段文档实现、自行验证、用通俗中文向 owner 汇报 |

## 3. 产品目标与边界

- 平台：**网页**（手机浏览器 + 电脑浏览器），不做原生 App、不做小程序
- 画面：**2D**，简洁扁平风，界面语言为**简体中文**
- 人数：**真人 1-4 名 + 可选电脑玩家，合计上限 4**（例如 1 真人 + 3 电脑的单人局、3 真人 + 1 电脑的凑局都可以；开局至少 2 名玩家）
- 联机：房间码加入，**无账号系统**，昵称即身份
- 使用范围：内部亲友游玩，**不公开发布、不商用**（因此《大富翁》商标与规则版权不构成风险；此边界改变时需重新评估法律问题）

## 7. 协作铁律（执行 agent 必须遵守）

Owner 不读代码，意味着 **agent 的自我验证是缺陷与上线之间唯一的安全网**。以下为硬规则：

1. **先讨论后动手**：改变任何产品行为（规则、流程、界面表现）前，先用通俗中文向 owner 说明并获确认。纯技术实现细节由 agent 自行决定，不要拿"用什么库"这类问题去问 owner。
2. **证据先于断言**：没有在本次会话中亲自运行并看到结果，就不得声称"能跑/测试通过/功能正常"。没验证的就明说"未验证"。
3. **测试先行**：规则引擎的每条规则先写测试再写实现（详见各阶段文档的验证要求）。
4. **看你看不见的东西**：UI 改动必须以截图或浏览器实测确认视觉效果，不得只凭代码推断"应该长这样"。
5. **独立评审**：每阶段收尾前，将产出交给一个独立的 review agent 审查一遍，修完问题再向 owner 汇报。
6. **通俗汇报**：向 owner 汇报只讲可观察的结果（例如"现在有人掉线后重新打开网页会回到原来那局"），不讲代码内部；涉及取舍时把后果翻译成 owner 能判断的语言。
7. **最小改动**：只做当前阶段文档要求的事，不顺手重构、不加计划外功能。发现计划外的问题先登记（见 §9），不擅自扩大战场。
8. **规则疑义回到 01**：实现中发现规则说不清的情况，先查 01 号文档；文档也没写的，向 owner 用大白话提问（举例说明场景），并把结论补进 01。

## 9. 工程约定

- **版本管理**：开工第一件事 `git init`（若尚未初始化）；每完成一个里程碑提交一次；commit message 用英文
- **代码注释**：中文；变量/函数/类名：英文
- **偏差记录**：实现与计划文档不一致时（无论原因），在对应文档末尾追加"## 实施偏差记录"小节，写明：日期、偏差内容、原因、owner 是否知情
- **进度标记**：README.md 中的"当前进度"必须在每阶段开始/结束时更新
- **技术栈**（详见 [03](03-架构与联机协议.md)，此处仅索引）：pnpm monorepo；客户端 Vue 3 + TypeScript + Vite；服务器 Node.js 20 + Socket.IO；规则引擎为独立共享包；测试 Vitest + 浏览器自动化

## 10. 第一版明确不做

账号系统 / 好友关系 / 游戏内聊天（玩家用微信语音即可）/ 电脑玩家难度分级（电脑玩家本身**要做**，见决策 6；难度档不做）/ 自定义地图编辑器 / 排行榜与战绩统计 / 多房间大厅列表（有房间码就够）/ 国际化（只做中文）/ 原生 App。

任何人想加这些，先找 owner 立项，不属于本计划范围。

观战模式已由 owner 追加立项：联机 6 个参赛席之外提供 3 个只读观战席，详见 06 号文档“联机六人 + 三个观战席”。
