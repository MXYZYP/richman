# 04 · 阶段 1 实施计划：单机热座版

> **目标**：在一台设备的浏览器里，2-4 名玩家轮流操作同一屏幕（"热座"），用真实棋盘数据打完一整局。规则引擎与 UI 在本阶段成型，联机（阶段 2）只是把引擎搬个家。
>
> - **前置条件**：阶段 0 完成——`pnpm validate-data` 全绿、01 号文档 §14 全部勾选、核对表经 owner 确认
> - **本阶段产出**：可完整游玩的热座版网页 + 全绿的规则测试集
> - **规则范围**：01 号文档 §15 "阶段 1" 列（无抵押、无交易、无 custom 卡）
> - **技术依据**：架构、目录、引擎接口全部按 03 号文档执行；美术按 02 §4 执行

## 1. 工作方式要求

- 引擎开发**严格测试先行**：每条规则先写 Vitest 用例（引用 01 的小节号作为用例注释），看它失败，再实现到通过。
- UI 每完成一块，用浏览器实际打开查看（截图确认），不凭代码想象。
- 里程碑顺序执行，每个里程碑结束 `git commit`（英文 message）。

## 2. 里程碑与任务分解

### M1 · 工程骨架

- [ ] `git init`（若未初始化）；建立 03 §2 的 monorepo 结构：`apps/client`、`packages/engine`、`packages/board-data`（`apps/server` 本阶段只建空目录占位）
- [ ] 根 `package.json` 提供 `pnpm dev / test / validate-data / build`（03 §2 命令表）
- [ ] Vue 3 + Vite + Pinia 空应用可启动；Vitest 空套件可运行；Vite dev 允许局域网访问（`--host`，供 owner 用手机试玩开发版）
- **验证**：`pnpm dev` 打开有占位首页；`pnpm test`、`pnpm validate-data` 正常退出

### M2 · 规则引擎（TDD，工作量大头）

按下列顺序逐条"先测后写"，用例命名对应 01 号文档小节：

- [ ] `createGame`：初始资金 15000、起点位置、掷骰定序（01 §3）、seed 确定性（同 seed 两次创建结果全等）
- [ ] 掷骰与移动：点数前进、绕圈取模、经过/恰停起点报酬金（01 §4.1，E01、E02、E21）
- [ ] 无主地产：买 / 放弃（含现金不足不可买；放弃后保持无主，无拍卖）
- [ ] 过路费：normal 六档（空地/1-4 房/旅馆）、station 按持有数取档、utility ×10/×100 按当次骰点、抵押中不收费预留（01 §6.1，E06-E09）
- [ ] 盖房（停留制，本版核心特色）：停自己地产可盖一幢、一次停留仅一幢、第五幢成旅馆、满级不可再盖、可跳过（01 §6.3，E03-E05）
- [ ] 卖房/卖地：半价返还、旅馆逐级卖回、卖地变无主可再购（01 §6.4/§6.5，E10、E11）
- [ ] 税格（01 §5）
- [ ] 卡牌：§9 全部 effect 类型各至少 1 例 + 抽牌放回堆底 + 出狱卡保留与归还来源牌堆（E16）；用真实 `cards.json` 逐张跑一遍不报错
- [ ] 债务与破产（无抵押版）：卖房+卖地筹款、对玩家/对银行破产、地产变无主、出局跳过（01 §11，E12-E15、E17）
- [ ] 胜利判定：最后存活 + 现金目标房规（01 §12，E18）
- [ ] 电脑玩家策略（03 §4.4）：各决策点行为符合策略 v1；**合法性属性测试**——任意可达状态下 `chooseBotIntent` 的产出必须被 `applyIntent` 接受（复用仿真骨架）
- [ ] **随机自弈仿真**：写一个"只发合法 intent 的随机机器人"，固定 seed 跑 ≥500 局：全程无异常、每局在 5000 个 intent 内正常终局或状态始终合法、玩家现金永不为负（债务状态除外）
- **验证**：`pnpm test` 全绿；01 §13 的 E01-E21 每条至少对应一个用例（在测试文件中以 `// E0x` 注释标记，缺一不可；E08/E16/E19/E20 为监狱模块用例，本版标注"不适用"即可）

### M3 · 棋盘与游戏 UI

- [ ] 棋盘组件：按 `board.json` 数据驱动渲染正方形环（格数不写死），格子样式按 02 §4.2
- [ ] 玩家资产条、棋子渲染、同格多棋子错位
- [ ] 掷骰动画 + 棋子按 `token_moved.path` 逐格跳动 + 事件结果弹層（动画播放序列由事件流驱动，03 §4.3）
- [ ] 操作面板：按 `turnPhase` 显示可用按钮（掷骰/买/放弃/盖房/跳过/卖房/卖地/结束回合），不可用即隐藏或置灰并给原因
- [ ] 地契卡浮层（点击任意格）、卡牌展示浮层、债务状态引导界面（提示还差多少、能卖什么）
- [ ] 事件日志面板；破产提示与胜利结算画面
- [ ] 开局设置页：真人数与电脑数（合计 2-4、真人 ≥1）、输入昵称、可选现金目标房规、开始
- [ ] 电脑回合自动执行：动作间隔 0.8~1.6 秒（03 §4.4），头像带机器人标识
- [ ] 热座回合交接：回合开始时明显的"轮到 ××"提示（大富翁无隐藏信息，无需遮屏）
- [ ] 手机竖屏 + 桌面两种布局（02 §4.4）
- **验证**：每个组件完成后浏览器截图自查；两种布局各留全局截图
  - M3-1 静态棋盘骨架截图：`plan/assets/screenshots/phase1/m3-1-board-desktop-1440x900.png`
  - M3-1 静态棋盘骨架截图：`plan/assets/screenshots/phase1/m3-1-board-mobile-390x844.png`

### M4 · 整局联调

- [ ] Agent 用浏览器自动化亲自打一整局 4 人热座（可加速动画），覆盖：买地、收租、盖房、抽两类卡、进出监狱、一次破产、打到胜利画面
- [ ] 手机尺寸（390×844）与桌面尺寸（1440×900）各完整截图关键画面：开局、棋盘中盘、地契卡、债务界面、胜利结算
- [ ] 修掉过程中发现的全部问题后，交独立 review agent 审查（代码 + 截图 + 测试报告）

## 3. 验收标准

**Agent 必须提交的证据**：

1. `pnpm test` 输出（全绿，含用例总数）；`pnpm validate-data` 输出
2. E01-E18 与测试用例的对照清单
3. 两种尺寸的关键画面截图
4. 自动打完整局的过程说明（用了什么工具、覆盖了哪些规则点）
5. 独立 review 的结论与修复记录

**Owner 验收清单**（用大白话逐条试）：

- [ ] 电脑浏览器打开，能建一局 3 人游戏，输入昵称开始
- [ ] 点"掷骰子"有骰子动画，棋子逐格走
- [ ] 走到空地能买，买完格子出现你的颜色条；别人走到你的地会自动扣过路费给你，有明确提示
- [ ] 再次走到**自己的地**时可以选择盖一幢房，格子上房子图标增加，过路费按产权卡表格上涨；盖到第五幢变成红色旅馆
- [ ] 缺钱时能把房子半价卖掉，也能把没盖房的地半价卖回银行
- [ ] 抽到机会/命运卡会展示卡面文字，效果和文字一致
- [ ] 有人钱不够会进入"卖房卖地筹钱"流程，实在不行破产出局，剩余现金归债主、地产变回无主
- [ ] 开局若设了"现金目标"（如 30000），有人现金先达标立即获胜
- [ ] 打到只剩一人，出现胜利画面
- [ ] 能加电脑玩家：你一个人 + 3 个电脑也能打完整局，电脑会自己掷骰、买地、盖房、还债
- [ ] 手机浏览器打开同一网址（同 WiFi 下访问开发地址），竖屏下也能顺畅玩
