# 07 · 阶段 4：部署指南

> **目标**：让亲友们真的能连上玩。两条路径独立成篇：**路径 A** 聚会同 WiFi（零成本）、**路径 B** 云服务器（随时随地）。两条都要（owner 决策 #1）。
>
> - **前置条件**：阶段 2 验收通过即可部署（阶段 3 完成后重复"更新"步骤即可）
> - **读者**：owner 本人 + 陪同操作的 agent。标 🤖 的步骤由 agent 执行，标 👤 的需要 owner 动手（多为付钱、扫码、拿手机试）
> - **原理背景**：生产形态是"一个 Node 进程一个端口"（03 §2），所以部署 = 把这个进程跑在一台大家都访问得到的机器上

## 路径 A · 聚会模式（同一 WiFi，零成本）

**适用**：大家在同一屋檐下（家庭 WiFi）。owner 的 Mac 当主机。

### A1 一键启动

- 🤖 实现 `pnpm party` 脚本（阶段 2 交付物的一部分，若缺补上）：构建（有代码更新时）→ 启动服务器 → 探测本机局域网 IP → 终端打印 `http://192.168.x.x:3000` 与对应二维码；同时游戏首页角落常驻一个"邀请二维码"按钮，点开全屏展示，方便传阅扫码
- 👤 之后每次聚会：打开终端，进入项目文件夹，输入 `pnpm party`，回车（agent 会在首次部署时帮 owner 在桌面放一个双击即可运行的快捷方式，例如 `.command` 文件）

### A2 手机加入

- 👤 手机连**同一个 WiFi** → 扫码 → 浏览器打开 → 输昵称建房/加房间码

### A3 常见问题（聚会现场排查顺序）

| 症状 | 依次检查 |
|---|---|
| 手机打不开页面 | ① 手机连的是不是同一个 WiFi（不是蜂窝、不是访客网络）② 首次启动时 macOS 弹的"是否允许 node 接受网络连接"要点**允许**（在 系统设置→网络→防火墙 可补救）③ 部分路由器开了"AP 隔离/访客隔离"，需在路由器设置里关闭 |
| 电脑休眠后大家掉线 | 聚会期间把 Mac 设为不休眠（系统设置→锁定屏幕）；游戏本身支持重连，唤醒后各自刷新即可回局 |
| 中途想换电脑当主机 | 把项目文件夹拷过去重新 `pnpm party`；**进行中的牌局**在 `apps/server/saves/` 里，连同拷贝即可延续 |

## 路径 B · 云服务器（随时随地远程玩）

**适用**：各自在家。需要一台 7×24 在线的小云服务器。

### B0 方案与费用（先看这个再花钱）

| 项目 | 说明 | 费用量级（以官网实时价为准） |
|---|---|---|
| 云服务器（必需） | 腾讯云/阿里云"轻量应用服务器"最低配（2 核 2G 足够富余，本游戏 4 人负载极小） | 新用户促销常见 ¥50~100/**年**；常规约 ¥25~60/**月** |
| 域名（可选，默认不买） | 不买域名就用 `http://服务器IP:3000` 访问，完全够用 | ¥50~80/年 |
| ICP 备案（可选） | 只有"域名 + 国内服务器"才需要；用 IP 直连**不需要备案** | 免费但流程数周 |

**默认推荐组合：国内区域轻量服务器 + IP 直连，不买域名、不备案。** 想要好记的网址和 https 时，再走 B5 的可选升级。

区域选择：就近（如广州/上海/北京）。微信里直接打开 `http://IP:3000` 链接可用；个别情况提示"非安全链接"点继续即可。

### B1 购买（👤 owner 操作，agent 在旁指引）

1. 注册/登录腾讯云 → 产品"轻量应用服务器" → 新建
2. 区域选就近；镜像选 **Ubuntu 22.04 LTS**；套餐选最低配；时长按预算（可先买 1 个月试水）
3. 设置 root 密码（记好）；记下**公网 IP**

### B2 防火墙放行（👤 在腾讯云控制台点，agent 指引）

轻量服务器控制台 → 防火墙 → 添加规则：放行 **TCP 3000**（游戏）；**TCP 22**（SSH，装完可收紧来源 IP）。

### B3 首次部署（🤖 agent 通过 SSH 执行，owner 提供 IP 和密码）

```bash
# 1) 登录服务器
ssh root@<公网IP>

# 2) 安装 Node.js 20 与 pnpm、pm2（进程守护，负责崩溃自动拉起、开机自启）
curl -fsSL https://deb.nodesource.com/setup_20.x | bash - && apt-get install -y nodejs
npm i -g pnpm pm2

# 3) 获取代码（二选一）
#    a. 项目已托管在 GitHub/Gitee 私有仓库（推荐，agent 先协助 owner 建仓推送）：
git clone <私有仓库地址> /opt/richman
#    b. 无仓库：agent 在本地打包，用 scp/rsync 上传到 /opt/richman

# 4) 构建并启动
cd /opt/richman && pnpm install && pnpm build
pm2 start "pnpm start" --name richman
pm2 save && pm2 startup   # 按提示执行输出的那行命令 → 开机自启

# 5) 基础加固（一次性）
apt-get install -y unattended-upgrades   # 系统安全补丁自动装
```

- 🤖 验证：`pm2 status` 显示 online；agent 用浏览器访问 `http://<公网IP>:3000` 完整建房加入走两回合
- 👤 验证：自己手机（**关掉 WiFi 用流量**，模拟真实远程）打开该网址，能建房间；再拉一位亲友异地加入实测

### B4 日常维护速查（🤖 agent 执行，owner 只需转述症状）

| 想做什么 | 命令 |
|---|---|
| 更新到最新版本 | `cd /opt/richman && git pull && pnpm install && pnpm build && pm2 restart richman`（进行中的牌局会经历一次重启，玩家刷新即回局） |
| 看运行状态 / 日志 | `pm2 status` / `pm2 logs richman --lines 200` |
| 备份进行中的牌局 | 打包 `/opt/richman/apps/server/saves/` |
| 服务器重启后 | 无需操作（pm2 开机自启 + 存档恢复，玩家刷新回局） |

### B5 可选升级：域名 + HTTPS

需要"好记网址 + 小锁标志"时：买域名 → 若服务器在国内区域需 ICP 备案（数周），或改用**香港区域**服务器免备案（延迟略增，内部游玩通常无感）→ 服务器上装 Caddy 反向代理到 3000，自动签发证书。此路径按需执行，agent 届时给出逐步指令；不影响 IP 直连方式继续可用。

### B6 故障排查

| 症状 | 依次检查 |
|---|---|
| 完全打不开 | ① 控制台防火墙 3000 是否放行 ② `pm2 status` 是否 online ③ 服务器是否欠费停机 |
| 能开页面但连不上房间 | `pm2 logs` 看报错；确认访问的是 `http://` 而非 `https://`（IP 直连没有证书） |
| 延迟明显 | 区域是否离玩家太远；服务器带宽套餐是否被占满（本游戏流量极小，一般不会） |
| 玩着玩着全员掉线后回不来 | `pm2 logs` 查是否进程崩溃重启；存档机制应能恢复，若恢复失败属 bug——记录日志交执行 agent 修复 |

## 安全边界说明（owner 须知，大白话）

- 这台服务器上**只有这个游戏和牌局存档**，没有任何个人敏感数据；最坏情况是陌生人猜到 IP 和房间码来蹭玩或捣乱——内部使用风险很低，若发生，换个房间码即可
- root 密码/SSH 密钥不要发到群里；给 agent 用完可改密
- 若未来想公开给更多人玩，需重新评估（防滥用、版权、备案），不在本计划范围
