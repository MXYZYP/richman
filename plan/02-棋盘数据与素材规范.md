## 2. 数据文件

三个数据文件放在 `packages/board-data/data/`，是游戏内容的唯一来源：

```
packages/board-data/data/
├── board.json        # 棋盘每一格（布局来自核对表表 A/A2；地产数值来自 raw/ 两份地皮 md）
├── cards.json        # 机会/命运卡（来自核对表表 B，源头 raw/机会卡.md、raw/命运卡.md）
└── game-config.json  # 全局数值（字段与定案值见 01 号文档 §2）
```

### 2.3 校验脚本（转录完成的硬性关卡）

在 `packages/board-data` 内实现 `pnpm validate-data`，全部通过才算数据完成：

- [ ] cells 的 `id` 从 0 连续递增无缺号；`type`/`subtype` 为合法枚举；有且仅有一个 `start`
- [ ] **名称对账**：board.json 中 `subtype=normal` 的名称集合与《raw/大富翁-普通地皮.md》35 行完全一致；station/utility 名称与《raw/大富翁-非普通地皮.md》6 行完全一致（不多、不少、不错字）
- [ ] **数值对账**：每块地产的 price/houseCost/rents/mortgageValue 与地皮 md 文件逐项一致（脚本直接解析两份 md 作对照源）
- [ ] normal 的 `rents` 长度 = 6 且严格递增；station 的 `rents` 长度 = 4；utility 无 `rents`
- [ ] `mortgageValue` = `price × 0.5`（数据已验证符合此规律，脚本做提示性校验，不一致则警告人工复核）
- [ ] **监狱反向校验**（K1 已定案为无）：board.json 不应出现 `go_to_jail`/`jail_visit` 格，cards.json 不应出现"进牢/出狱许可证"卡，`jailEnabled` 必须为 false（转录已人工验证 30 张卡无此类卡，脚本兜底防手误）
- [ ] **卡牌对账**：cards.json 与 `raw/机会卡.md`（15 张）、`raw/命运卡.md`（15 张）逐张一致（编号、金额、张数）
- [ ] 每张卡、每个 `world`/`special` 格的 effect 参数完整（`move_to.cellId` 必须存在于棋盘；`draw_card.deck` 为合法牌堆名）
- [ ] **移动图连通性**：沿 next 指针从起点出发能走完外环回到起点；支线从 `branchEntryId` 出发能汇回外环；无死路、无指向不存在格子的指针
- [ ] `game-config.json` 含 01 §2 全部字段且类型正确
- [ ] 统计输出：格子总数、各类型数量、卡牌张数，供与照片人工比对

## 3. 转录流程（阶段 0 的执行步骤）

> **进度（2026-07-05）**：步骤 1-3 已完成——全景照片 + owner 口述 + 卡牌文字版均已到位，核对表（表 A/A2/B）录满，K8 与 71-13 也已由 owner 答复关闭（01 §14 全关）。**执行 agent 从步骤 4 开始**。
>
> 执行本流程的 agent 必须具备看图能力（若还需看照片）。**禁止编造**——拿不准就标注问 owner。地产价格**不得**从照片转录，一律以 `raw/` 两份地皮 md 文件为准（已是文字版权威）；卡牌以 `raw/` 两份卡牌 md 为准。

1. **收照片**：按 §1 清单核对齐全，存入 `plan/assets/photos/`，纳入 git。
2. **产出核对表**：新建 `plan/assets/棋盘数据核对表.md`：
   - 表 A：棋盘逐格清单（id、类型、名称），按照片沿行进方向逐格列出；税格含金额；
   - 表 B：全部卡牌（原文、拟定的 effect 类型与参数）；
   - 表 C：01 号文档 §14 中仍开放的 K8-K12 各项的关闭结论与依据（K1-K7 已由 owner 定案，见 01 §14"已关闭"表）；
   - 读不清、拿不准的地方标 ❓ 列成问题清单。
3. **Owner 确认**：owner 对照实体版核对（这是 owner 唯一需要细看的文档），答复 ❓。
4. **生成 JSON**：按核对表 + 两份地皮 md 生成三个数据文件，跑 `pnpm validate-data` 到全绿。
5. **回填规则书**：01 §14 逐项关闭；与默认方案不同的结论同步修订 01 正文。
6. **完成标志**：校验全绿 + owner 确认核对表 + 01 §14 全关闭 → 更新 README 进度，阶段 1 开工。

### 4.2 棋盘与格子

- 正方形环布局（格数按数据渲染，**不写死**；本棋盘格数多于标准版，四边每边约 12-13 格，格子宽度自适应）；中央区域放骰子、当前事件提示和牌堆。
- 普通格：顶部 22% 为飞书 A 列匹配色带，下方名称（2-4 字换行）；手机版局部地图可显示裸地售价，手机版全局棋盘格不显示裸地售价。盖房后色带上叠加等级标志——1-4 幢小房子图形，第 5 级换**红色旅馆**图形（呼应说明书"红色房屋"）。
- 角格与功能格（本棋盘实有：起点、机场、兰州牛肉面休息格、香港维多利亚港、所得税、机会、命运、9 个支线格）：内联 SVG 简笔图标 + 名称。机会 `?`、命运 `!`、税 `¥`、起点 `→`、机场飞机、休息格面碗、维港夜景月亮、支线格小地球。**地产格不做单独图标**（41 个图标是工作量黑洞）。
- 玩家棋子：4 个实心圆 token，红/蓝/黄/绿 + 形状记号（圆/方/三角/星，色盲友好），同格多人错位排列（说明书二：代表物可同停一格）；电脑玩家的头像与资产条条目带机器人小标识以区分真人。
- 所有权标记：格子内侧 4px 归属色条（跟玩家色）。抵押中：色条变灰 + "抵押"角标。

### 4.3 字体与数字

- 中文字体栈：`"PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`（系统字体，不引入网络字体）。
- 金额一律 `font-variant-numeric: tabular-nums`，千分位分隔，付钱红 `-`、收钱绿 `+`。

### 4.4 布局（两种断点）

**手机竖屏（<768px，优先设计）**：仅使用全局棋盘，显示完整地图、支线与所有玩家位置。局部聚焦视图及切换入口已按 v2.5.0 需求删除；地名、价格、归属等完整信息通过点选格子详情查看。

```
┌──────────────────────┐
│ 玩家资产条（4 人头像+现金，横向） │
├──────────────────────┤
│ 完整全局棋盘（无视图切换）      │
│ 短地名、归属色带、玩家棋子      │
├──────────────────────┤
│ 固定高度骰子台                 │
│ 固定操作区：掷骰/买地/放弃/    │
│ 结束回合/重抽与接受             │
├──────────────────────┤
│ 卡牌、当前位置、提示            │
│ 资产、格子详情、事件日志入口    │
└──────────────────────┘
```

**桌面/平板横屏（≥768px）**：左侧棋盘（尽量大的正方形），右侧纵向栏 = 玩家资产卡片 + 操作面板 + 完整事件日志。

- 手机与桌面均以全局棋盘为唯一棋盘视图。手机玩家栏保持座次与高度固定，主要操作按钮不随卡牌、地点或提示内容增减而上下移动。
- 格子较多、单格较小，全局棋盘在手机上以短名/色带/玩家 token 为主，详细名称、价格、六档过路费表、单栋建筑费、抵押价、当前所有者与等级由格子详情/产权卡承载。
- 掷骰：操作按钮上方的固定高度骰子台显示两颗 2D 骰子滚动动画（K2 定案：两颗骰子，点数和 2-12）；其他提示仍在按钮下方。
- 棋子移动：逐格跳动过渡动画，移动完成再弹结算结果。

### 4.5 明确不做

不做换肤、暗色模式、棋盘双指缩放（自适应+点格弹卡已够）、不引入 canvas 游戏引擎或图片素材库。若阶段 3 试玩后 owner 觉得画面单薄，再立项升级美术。
