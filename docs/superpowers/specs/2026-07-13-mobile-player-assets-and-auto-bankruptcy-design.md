# 手机玩家资产详情与自动破产设计

日期：2026-07-13
状态：用户已批准视觉方向与规则选择，待实施

## 1. 目标

本切片解决三个已确认问题：

1. 手机端“重新开局”位于棋盘与主要操作面板之间，容易挤占核心操作区；
2. 顶部玩家卡只能查看现金，无法点击查看该玩家的完整资产与房产；
3. 债务状态在所有筹款手段耗尽后不会自动结束，真人玩家可能永久停在欠款状态。

## 2. 已确认的产品行为

### 2.1 重新开局

- 仅调整手机端位置；桌面端保持现有布局。
- 手机端按钮放到整页内容末尾：操作面板、我的资产、格子详情、战报记录之后。
- 按钮仍使用现有 `requestExit` 与二次确认流程，不改变重新开局、离开在线房间或清理 session 的逻辑。
- 按钮不固定悬浮，不占用手机可玩区域。

### 2.2 点击玩家卡查看资产

- 顶部 `PlayerRail` 的三张玩家卡保持现有尺寸、顺序、颜色、当前玩家高亮与手机三卡同屏布局。
- 不新增“玩家”总入口，不收起或替换现有玩家栏。
- 每张玩家卡变为可点击、可键盘聚焦的按钮；点击谁，只打开该玩家的详情。
- 本地热座与在线模式共用同一套详情展示，数据来自当前可渲染游戏状态。

详情包含：

- 玩家头像、昵称；
- BOT、当前回合、离线、破产等已有状态；
- 当前现金；
- 当前所在格名称；
- 当前是否为欠款人及剩余欠款金额；
- 该玩家拥有的全部地产；
- 每块地产的短名、房屋/旅馆等级、抵押状态。

不在本切片计算或展示“净资产总值”，避免把地价、房屋成本、抵押价值与变卖价值混成一个未经确认的新规则口径。

### 2.3 详情弹层与大量房产

- 手机端使用底部弹层，最高约占视口 `80%`。
- 桌面端使用居中对话框；内容与手机端一致。
- 标题、玩家摘要和关闭入口保持可见；房产列表区域独立纵向滚动。
- 手机房产列表采用两列网格并自动换行；桌面可使用更多列。
- 不使用横向滚动。长地名可在卡片内换行，不能丢失房屋等级或抵押状态。
- 无房产时显示明确空状态。
- 支持关闭按钮、点击遮罩与 `Escape`；打开后焦点进入弹层，关闭后返回原玩家卡。
- 弹层只读。出售、抵押、赎回仍由现有“我的资产”面板处理，避免旁观其他玩家时误操作。

## 3. 欠款语义与自动破产

### 3.1 当前欠款不是贷款

强制付款高于现金时：

1. 先支付当前全部现金；
2. 玩家现金降到 `0`，不会变成负数；
3. `debt.amount` 只记录尚未支付的余额；
4. 正常流程冻结，只允许筹款或破产。

买地、盖房、赎回属于主动消费，余额不足时仍直接拒绝，不创建债务。

可创建债务的强制付款包括租金、税格、向银行付款的卡牌、维修费及玩家间多笔付款。

### 3.2 已确认的自动破产时机

用户选择：**资产耗尽后自动破产**。

具体规则：

1. 债务存在时，玩家仍自行选择卖哪栋房、抵押哪块地或卖哪块地；系统不提前替玩家批量清算。
2. 每次筹款后先运行现有立即还债逻辑：
   - 现金足够则立即支付剩余欠款并恢复流程；
   - 现金仍不足则继续检查可用筹款资产。
3. 当现金仍不足，且已经不存在任何合法筹款动作时，立即自动执行现有破产结算，不再要求真人点击“宣告破产”。
4. 新债务刚产生时若玩家本来就没有任何合法筹款资产，也立即自动破产。

“仍有合法筹款动作”定义：

- 拥有至少一块 `level > 0` 的普通地产，可卖一级房屋；或
- 拥有至少一块 `level === 0`、未抵押且有 `mortgageValue` 的地产，可抵押；或
- 拥有至少一块 `level === 0`、未抵押的地产，可卖回银行。

已经抵押的无房地产不能再次筹款；债务状态不能赎回后再出售。

### 3.3 自动破产沿用现有结算

自动破产必须与手动 `declare_bankrupt` 产生相同结果：

- 剩余现金交给玩家债主；债主为银行时现金离开游戏；
- 名下地产全部恢复无主；
- 房屋清零，抵押注销；
- 记录 `bankruptTurn`；
- 玩家出局，轮转跳过；
- 多笔付款存在时继续处理排队付款；
- 只剩一名未破产玩家时结束游戏；
- 债主因收到现金达到现金目标时沿用现有即时胜利逻辑。

手动“宣告破产”仍保留：玩家有可变现资产时也可以主动放弃并破产。

## 4. 组件与数据流

### 4.1 `PlayerRail.vue`

- 保持现有视觉 CSS 与三卡布局。
- 玩家卡改为语义化按钮。
- 新增 `select-player` 事件，负载为 `player.id`。
- 不在该组件内读取或计算地产，避免把展示条与完整游戏状态耦合。

### 4.2 `GameView.vue`

- 保存当前选中的 `selectedPlayerId`。
- 响应 `PlayerRail` 事件并打开详情。
- 从当前 `RenderableGameState` 派生选中玩家、位置名称、欠款状态与资产行。
- 在本地/在线 session 切换、玩家消失或游戏结束时安全关闭无效详情。
- 手机端重新开局按钮显示在内容末尾；桌面端保留原位置。

### 4.3 新玩家详情组件

新增专用只读组件，例如 `PlayerAssetDialog.vue`：

- 输入玩家摘要、位置、欠款与 `AssetRow[]`；
- 负责响应式弹层/对话框、关闭行为、焦点与滚动；
- 不发送引擎 intent。

复用现有 `getAssetRows(state, playerId)`，不新建第二套地产格式化逻辑。必要时仅扩展 `AssetRow` 的展示字段并迁移全部调用者。

### 4.4 引擎债务收口

- 提取可复用的“是否仍有合法筹款动作”判断。
- 将自动破产检查放在所有成功 intent 的债务收口路径，覆盖：
  - 掷骰/支线掷骰后产生的新债务；
  - 卖房、抵押、卖地后的剩余债务；
  - 多笔付款队列继续产生的下一笔债务。
- 复用同一破产核心函数，确保手动和自动路径不会出现两套资产清理、胜利或轮转逻辑。
- 避免重复写入 `recentLog` 或重复发送破产/终局事件。

## 5. 非目标

本切片不改变：

- 棋盘数据、卡牌数据、租金和税额；
- 买地、盖房、抵押、赎回、卖房、卖地的金额公式；
- 玩家卡现有排序与顶部布局；
- 其他玩家资产的操作权限；
- 在线公开快照字段；
- 重新开局/离开房间/session 清理语义；
- 交易、拍卖或净资产排名。

## 6. 验收标准

### UI

- 390×844 下顶部三张玩家卡仍同屏，尺寸和顺序不变。
- 点击每张卡都只显示对应玩家。
- 0、1、2、12 项房产均可正确显示；12 项时两列换行且弹层内部可滚动。
- 关闭后焦点回到原玩家卡。
- 手机端“重新开局”位于战报记录之后；桌面端位置不变。
- 重新开局二次确认与本地/在线退出语义不变。

### 引擎

- 强制付款先扣光现金，`debt.amount` 只等于未付差额。
- 有合法筹款资产时不自动破产。
- 卖掉/抵押最后一项可筹款资产后仍不足，立即自动破产。
- 新债务产生时完全无可筹款资产，立即自动破产。
- 足额筹款优先还债，不错误破产。
- 手动宣告破产仍可用并与自动路径结果一致。
- 玩家债主、银行债主、多笔付款、轮转和胜利条件均有回归测试。
