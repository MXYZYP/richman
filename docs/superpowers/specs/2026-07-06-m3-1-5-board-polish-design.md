# M3-1.5 棋盘美化设计

## 1. 目标

在 M3-2 交互接入前，先把 M3-1 的静态棋盘从“可用骨架”升级为“可比稿的桌游视觉版本”。本切片交付两类结果：

1. **结构修正**：不改变棋盘数据、格子 id、走法规则和 `boardLayout.ts` 坐标测试，只通过 DOM/CSS 升级棋盘观感与可读性。
2. **三套皮肤比稿**：在同一 DOM 上用 CSS 变量切换 A/B/C 三套主题，每套输出桌面与手机截图，共六张，供 owner 后续选择正式美术规范。

## 2. 已确认决策

- 采用 **CSS 结构升级 + 根级/页面级 theme 变量** 路线。
- 页面内提供皮肤切换开关。
- 皮肤切换开关放在操作面板顶部。
- 默认主题为 **A 实体复刻暖纸风**。
- 不采用 16×16 坐标重排；外环长条格与四角大格通过 CSS 非均匀 grid 轨道实现。
- 不改 `boardLayout.ts`、棋盘数据 JSON、engine state 结构或规则逻辑。

## 3. 范围

### 3.1 必做

1. 外环格改成长条比例，长边朝棋盘中央；四角格加大。桌面端应明显减少或消灭名称截断。
2. 中央区域替换 M3-1 占位虚线框，改为：
   - 斜置「大富翁·中国之旅」题字；
   - 骰子展示区；
   - 当前事件提示条。
3. 支线九格之间绘制虚线轨迹，方向清楚表达：机场 → 首尔 → 东京 → 机会 → 纽约 → 伦敦 → 巴黎 → 命运 → 曼谷 → 河内 → 黑龙江。
4. 操作面板按钮具备可用/禁用视觉态。M3-1.5 仍是静态切片，可以只演示视觉态，不接真实交互逻辑。
5. 地产价格提高字号和对比度。
6. 棋子保留颜色/形状区分，并加强白描边与微阴影。
7. 三套主题用 CSS 变量切换，并输出六张截图。

### 3.2 不做

- 不接掷骰、买地、盖房等真实交互。
- 不引入图片、网络字体、canvas 游戏引擎或图片素材库。
- 不改变棋盘数据、规则引擎、格子 id、外环/支线坐标测试。
- 不更新 `plan/02 §4.1/4.2` 的正式规范；owner 选定主题后再由评审方更新。

## 4. 结构设计

### 4.1 外环长条格与大角格

保留 M3-1 的 14×14 placement 语义：`boardLayout.ts` 仍输出 `row/col`，组件继续按 `gridRow/gridColumn` 放置格子。

视觉上通过 `.board-grid` 的非均匀轨道实现比例变化：第 1/14 行列比中间轨道更宽，角格因同时占用加宽行列而自然变大；边格因一条轴更宽而形成长条。这样能达到“长边朝内”和“四角加大”的视觉目标，同时不触碰数据层或测试层。

桌面端优先显示完整名称与价格；手机端继续优先显示短名/图标，避免 390px 宽度下拥挤。

### 4.2 中央区域

`center-panel` 从占位容器升级为三层结构：

1. 标题层：斜置「大富翁·中国之旅」，作为棋盘主视觉记忆点。
2. 骰子层：两颗 CSS/文本绘制骰子，M3-1.5 只做静态或轻微装饰，不做真实动画。
3. 事件条：胶囊条或票根条样式，承载「当前事件提示区域」占位文案。

三层在桌面可带轻微旋转和层次阴影；手机端可降低倾斜角度或改更紧凑布局，确保不遮挡支线。

### 4.3 支线虚线轨迹

在 `.board-grid` 内新增一层内联 SVG overlay，用虚线 polyline/path 连接支线格中心点。虚线层仅负责视觉指引，不参与点击和布局，设置 `pointer-events: none`。

支线格仍由 `state.board.cells` 数据驱动渲染；虚线轨迹使用与当前支线定位一致的百分比坐标，保证路径贴合九格位置。

### 4.4 操作面板与主题切换

`ActionPanel.vue` 顶部新增主题切换器：A / B / C 三个选项，默认 A。切换器可以用 Vue state 或根级 `data-theme` 驱动；最终实现应保证：

- 切换不会重建 game state；
- 不影响 board data 与规则；
- 当前选择在截图中可见；
- 按钮视觉态与所选主题一致。

操作按钮保留 disabled 语义，但视觉上区分：

- 可用态演示：主色填充、高对比文字、微阴影；
- 禁用态：低饱和底色、弱文字、无 hover 强反馈。

### 4.5 棋子与价格

棋子继续使用玩家颜色和形状（● / ■ / ▲ / ★）双重编码。视觉增强包括：

- 白描边更清晰；
- 微阴影让棋子从格子上“抬起”；
- 同格错位逻辑保持 M3-1 的按边界向内偏移策略。

价格区域提高字号、使用更深的文字色或主题价格色，并保持 `font-variant-numeric: tabular-nums`。

## 5. 主题设计

三套主题共享同一 DOM 和同一结构，只替换 CSS 变量。玩家身份色（红/蓝/黄/绿）应尽量跨主题保持稳定，避免切换主题后玩家识别混乱；棋盘地皮色带、背景、中心面板、航线、按钮可随主题变化。

### 5.1 A 实体复刻暖纸风（默认）

**一句话取舍**：最像实体桌游，亲切耐看，视觉冲击较克制。

- 背景：暖米色、纸板感、低饱和阴影。
- 外环：奶油白格底，暖灰描边，低饱和档次色带。
- 中央：深棕/中国红题字，纸票式事件条，暖色骰子区。
- 支线：暖棕虚线航线，城市格像护照印章。
- 按钮：厚卡纸/木质感，可用态暖棕或中国红，禁用态灰纸。

### 5.2 B 现代桌游深色风

**一句话取舍**：高级沉浸、夜间感强，但要避免过度电竞化。

- 背景：深炭灰、暗蓝灰棋盘底。
- 外环：深色格底，青蓝/琥珀/玫红等低面积亮色带。
- 中央：磨砂玻璃感面板，琥珀标题，状态栏式事件提示。
- 支线：青蓝发光虚线，像雷达航线。
- 按钮：深色玻璃按钮，可用态发光边或亮色底，禁用态暗灰。

### 5.3 C 国潮红蓝金风

**一句话取舍**：最有“中国之旅”记忆点，节庆感强，但需压住饱和度避免喧宾夺主。

- 背景：中国红与深蓝搭配，金色作为描边和强调。
- 外环：浅金/米白格底，蓝系地产色带，金色功能格边框。
- 中央：红底金字题字，卷轴式事件条，红金骰子。
- 支线：金色虚线航线，站点像印章或路引。
- 按钮：宫殿红/金色描边，可用态金底红字或红底金字，禁用态陶土灰。

## 6. CSS 变量策略

主题变量至少覆盖以下语义，不要求名字逐字一致，但实现时应保持语义清晰：

- 页面与棋盘：`--color-bg`, `--board-bg`, `--board-shadow`, `--board-gap`, `--color-cell`, `--color-border`
- 文字：`--color-text`, `--color-muted`, `--price-color`
- 中央：`--center-bg`, `--center-border`, `--title-color`, `--event-bg`, `--event-text`
- 支线：`--branch-track`, `--branch-track-shadow`
- 地产色带：`--band-feishu-d73a49`, `--band-feishu-1677ff`, `--band-feishu-8e44ad`, `--band-feishu-1f5fbf`, `--band-feishu-e66a95`, `--band-feishu-2ea44f`, `--band-feishu-c2185b`, `--band-feishu-757575`, `--band-station`, `--band-utility`
- 玩家：`--player-red`, `--player-blue`, `--player-yellow`, `--player-green`, `--token-ring`, `--token-shadow`
- 按钮：`--button-enabled-bg`, `--button-enabled-text`, `--button-disabled-bg`, `--button-disabled-text`

实现可选择根级 `:root[data-theme="a"]` 或页面级 `.theme-a`。当前已确认“根级/页面级 theme 变量”均可接受；实施计划中应选择一种并保持一致。若选择页面级 class，`App.vue` 持有当前 theme，`ActionPanel.vue` 通过 props/emit 切换。

1. `pnpm vitest run apps/client/src/ui/boardLayout.test.ts` 全绿。
2. `pnpm test && pnpm typecheck && pnpm validate-data && pnpm --filter @richman/client build` 全绿。
3. 六张截图均生成到指定路径。
4. 独立视觉复查确认：
   - 桌面端外环长条格与大角格明显；长名称不再主要依赖截断。
   - 中央题字、骰子区、事件条清楚。
   - 支线虚线轨迹方向一眼可读。
   - 按钮可用/禁用态有视觉差异。
   - 棋子边界和阴影清楚，同格仍可辨认。
   - 手机 390×844 无页面级横向裁切，短名/图标可读。
5. 输出三套皮肤的一句话取舍说明，供 owner 选择。

## 9. 风险与规避

- **误改坐标层**：禁止修改 `boardLayout.ts` 的 placement 语义；用 CSS grid 轨道解决比例问题。
- **主题变量遗漏**：实施后用搜索检查组件内残留裸色值，少量纯白描边可保留，但主题相关颜色应变量化。
- **深色主题可读性下降**：B 主题的发光半径和透明度要克制，价格和短名必须高对比。
- **国潮主题过度饱和**：C 主题用金色和红蓝做记忆点，但格内文字仍保持深色高可读。
- **手机信息过密**：手机端继续短名/图标优先，价格可隐藏或弱化，主题装饰降噪。
