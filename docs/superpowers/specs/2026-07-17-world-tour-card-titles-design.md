# World Tour Card Titles Design

Date: 2026-07-17  
Status: Approved

## 1. Goal

让“世界之旅”的机会卡和命运卡在抽取时同时展示主题标题与结算规则，解决当前界面只显示规则、缺少卡片主题的问题，同时保持“中国之旅”现有卡牌文字与规则完全不变。

## 2. Source authority

世界之旅卡片标题以飞书工作簿 revision 41 为准：

<https://bcne8a82ogna.feishu.cn/wiki/IsGfw6mqji8VeIkrqH2caBFOnGL>

工作表“机会卡”含 23 张卡，“命运卡”含 22 张卡。两张表的 C 列“卡片正文”统一采用“主题标题：结算规则”的结构，例如：

> 罗马斗兽场涂写罚款：向银行支付 1500 元。

实现时只在第一个中文或英文冒号处分隔：冒号前保存为卡片标题，现有 `text` 继续保存已经确认的结算规则。界面不重复显示冒号后的规则。

## 3. User-visible behavior

抽到带标题的世界之旅卡牌时，操作面板按以下层级展示：

1. 牌堆类型：`机会` 或 `命运`；
2. 主题标题，例如“罗马斗兽场涂写罚款”；
3. 结算规则，例如“向银行支付 1500 元。”。

标题比结算规则更醒目，但沿用现有暖纸卡片样式，不新增弹窗、插画或独立卡面资源。卡片仍按现有停留时长展示，桌面和手机使用同一数据与组件。

中国之旅卡牌不新增标题数据。卡牌没有标题时，操作面板继续使用当前单段文字布局，不增加空白标题，也不拆分或改写原文字。

## 4. Data contract

`Card` 新增可选展示字段：

```ts
export interface Card {
  id: string;
  title?: string;
  text: string;
  effect: CellEffect;
}
```

- `title` 只承担展示职责，不参与规则结算。
- `text` 继续是结算规则的权威显示文字，现有 engine、bot 和事件语义不变。
- 世界之旅 45 张卡必须全部提供非空 `title`。
- 中国之旅现有卡牌数据不修改，继续合法地省略 `title`。
- 地图校验允许可选 `title`；字段存在时必须是去除首尾空白后仍非空的字符串。

世界之旅版本化地图包内容发生变化，因此必须重新计算内容 hash，并同步更新 manifest、catalog 及直接断言旧 hash 的测试。hash 变化只表示地图包内容版本校验发生变化，不引入数据迁移或新的联机协议。

## 5. Client data flow

权威快照中的卡牌仍由 server 或本地 engine 提供。`GamePresenter` 在处理 `card_drawn` 时，从快照卡牌数据读取可选 `title`，并把它连同现有 `deck`、`cardId` 和 `text` 放入 `DisplayCard`。

`ActionPanel` 的卡牌预览按以下规则渲染：

- `title` 存在：显示牌堆类型、标题、结算规则；
- `title` 不存在：显示牌堆类型和现有单段 `text`；
- 找不到卡牌数据：沿用当前以 `cardId` 兜底的行为，不伪造标题。

事件动画、最终快照配对、联机权威状态、断线恢复和隐藏标签页恢复均不改变。标题是快照已有卡牌数据中的可选展示字段，不增加 client 自行执行规则的路径。

## 6. Scope boundaries

本次只处理卡片标题展示，不包含：

- 修改任何机会卡或命运卡的 effect；
- 调整牌库数量、顺序或随机逻辑；
- 修改卡牌停留时长；
- 修改中国之旅卡牌文案；
- 把飞书中的说明列、备注列或线下背景文字录入游戏；
- 向飞书工作簿写回数据；
- 新增卡牌插画、音效或动画。

## 7. Validation

必须覆盖以下行为：

1. 世界之旅 23 张机会卡和 22 张命运卡都有非空标题，且标题与飞书 revision 41 对应；
2. 地图校验接受合法的可选标题，并拒绝空标题或非字符串标题；
3. presenter 在世界之旅 `card_drawn` 时保留标题与结算规则；
4. presenter 处理无标题的中国之旅卡牌时保持原行为；
5. 操作面板在有标题和无标题两种输入下都能正确渲染；
6. 世界之旅新内容 hash 与 manifest、catalog 一致；
7. focused tests、完整测试、typecheck、`validate-data`、build 和 500 局仿真保持通过；
8. 在真实浏览器检查 1440×900 与 390×844，确认标题、规则可读且无横向溢出。
